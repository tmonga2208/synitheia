# XP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make XP real — a lifetime record of effort, awarded per action, on an append-only ledger that cannot double-award.

**Architecture:** The rules of *what an action earns* live in one pure module in `@synitheia/shared`, unit-testable without Mongo. A new `XpAward` collection carries a unique index on `{ userId, key }`, so every award is idempotent by construction. `user.xp` remains as a cache of the ledger sum, incremented only when an insert actually happened. Three services call the same `grantAwards` helper; none of them knows the amounts.

**Tech Stack:** TypeScript, zod, Fastify, Mongoose, vitest + `mongodb-memory-server`.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-08-02-xp-design.md`. Read it before starting.
- **XP never decreases.** No award is ever revoked, reversed, or deducted. Un-completing a habit does not take XP back.
- **Idempotence is structural, not careful.** Every award goes through the unique index. Never "check if it exists, then insert" — that races.
- **Dates are `LocalDate` in the user's own IANA timezone**, never the server's clock. Every dedupe key derives from one.
- **The amounts live in exactly one place** — `@synitheia/shared`. A service that hardcodes a number is a defect.
- **No scheduler.** Nothing in this app runs on a cron. Month-end work is lazy on a Today load, following `postDueSubscriptions`.
- **Never scold.** No award may produce a message about falling short. A month over budget earns nothing and says nothing.
- **Test runner:** `pnpm --filter @synitheia/shared test`, `pnpm --filter @synitheia/api test`. Full gate: `pnpm check`.
- Commit prefixes: `feat(shared):`, `feat(api):`.

- [ ] **Step 1: Write the failing test**

Create `packages/shared/src/domain/xp.test.ts`:

```ts
import { describe, expect, it } from 'vitest';
import { asLocalDate } from '../time/local-date.js';
import {
  XP_AMOUNTS,
  awardForMonth,
  awardsForHabitLog,
  awardsForWaterEntry,
} from './xp.js';

const DAY = asLocalDate('2026-08-02');
const HABIT = '6a6e43f1c18dd7ea6400da86';

describe('awardsForHabitLog', () => {
  it('awards nothing when the habit is not complete', () => {
    expect(
      awardsForHabitLog({
        habitId: HABIT,
        localDate: DAY,
        complete: false,
        currentStreak: 3,
        scheduledCount: 3,
        completedCount: 1,
      }),
    ).toEqual([]);
  });

  it('awards the habit itself on completion', () => {
    const awards = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 1,
      scheduledCount: 3,
      completedCount: 1,
    });

    expect(awards).toEqual([
      { key: `habit:${HABIT}:2026-08-02`, amount: XP_AMOUNTS.habitComplete },
    ]);
  });

  it('adds the day bonus only when every scheduled habit is done', () => {
    const partial = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 1,
      scheduledCount: 3,
      completedCount: 2,
    });
    expect(partial.map((a) => a.key)).not.toContain('day:2026-08-02');

    const full = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 1,
      scheduledCount: 3,
      completedCount: 3,
    });
    expect(full).toContainEqual({ key: 'day:2026-08-02', amount: XP_AMOUNTS.dayComplete });
  });

  it('does not award a day bonus when nothing was scheduled', () => {
    const awards = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 1,
      scheduledCount: 0,
      completedCount: 0,
    });
    expect(awards.map((a) => a.key)).not.toContain('day:2026-08-02');
  });

  it('awards a streak milestone at the boundary and not before', () => {
    const six = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 6,
      scheduledCount: 1,
      completedCount: 1,
    });
    expect(six.map((a) => a.key)).not.toContain(`streak:${HABIT}:7`);

    const seven = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 7,
      scheduledCount: 1,
      completedCount: 1,
    });
    expect(seven).toContainEqual({
      key: `streak:${HABIT}:7`,
      amount: XP_AMOUNTS.streak[7],
    });
  });

  it('offers every milestone at or below the current streak', () => {
    // Not "exactly equals": a recomputed streak can arrive already past a milestone,
    // and the ledger's unique index makes re-offering an already-granted one free.
    const awards = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 30,
      scheduledCount: 1,
      completedCount: 1,
    });

    expect(awards.map((a) => a.key)).toEqual(
      expect.arrayContaining([`streak:${HABIT}:7`, `streak:${HABIT}:30`]),
    );
    expect(awards.map((a) => a.key)).not.toContain(`streak:${HABIT}:100`);
  });

  it('never returns a zero or negative amount', () => {
    const awards = awardsForHabitLog({
      habitId: HABIT,
      localDate: DAY,
      complete: true,
      currentStreak: 100,
      scheduledCount: 1,
      completedCount: 1,
    });
    for (const a of awards) expect(a.amount).toBeGreaterThan(0);
  });
});

describe('awardsForWaterEntry', () => {
  it('awards nothing below the target', () => {
    expect(
      awardsForWaterEntry({ localDate: DAY, totalMl: 2499, targetMl: 2500 }),
    ).toEqual([]);
  });

  it('awards on reaching the target exactly', () => {
    expect(
      awardsForWaterEntry({ localDate: DAY, totalMl: 2500, targetMl: 2500 }),
    ).toEqual([{ key: 'water:2026-08-02', amount: XP_AMOUNTS.waterTarget }]);
  });

  it('awards once past the target, with the same key', () => {
    const awards = awardsForWaterEntry({ localDate: DAY, totalMl: 9000, targetMl: 2500 });
    expect(awards).toEqual([{ key: 'water:2026-08-02', amount: XP_AMOUNTS.waterTarget }]);
  });
});

describe('awardForMonth', () => {
  it('awards when the month closed within budget', () => {
    expect(awardForMonth({ month: '2026-07', spentMinor: 40000, budgetMinor: 50000 })).toEqual(
      { key: 'budget:2026-07', amount: XP_AMOUNTS.monthInBudget },
    );
  });

  it('awards when spending exactly equals the budget', () => {
    expect(
      awardForMonth({ month: '2026-07', spentMinor: 50000, budgetMinor: 50000 }),
    ).not.toBeNull();
  });

  it('awards nothing over budget — and never a deduction', () => {
    expect(awardForMonth({ month: '2026-07', spentMinor: 50001, budgetMinor: 50000 })).toBeNull();
  });

  it('awards nothing when no budget is set', () => {
    expect(awardForMonth({ month: '2026-07', spentMinor: 0, budgetMinor: null })).toBeNull();
  });
});
```

## Task 2: The ledger and `grantAwards`

**Files:**
- Modify: `apps/api/src/db/models.ts`
- Create: `apps/api/src/modules/xp/service.ts`
- Test: `apps/api/src/modules/xp/service.test.ts`

**Interfaces:**
- Consumes: `XpAward` from `@synitheia/shared`
- Produces: `grantAwards(userId: string, awards: readonly XpAward[]): Promise<number>` — returns the XP actually granted, which is `0` when every award was a duplicate.

- [ ] **Step 1: Add the model**

In `apps/api/src/db/models.ts`, following the existing schema style:

```ts
const xpAwardSchema = new Schema(
  {
    userId: { type: Schema.Types.ObjectId, ref: 'User', required: true },
    /**
     * What was earned, as a stable string — `habit:<id>:<localDate>`, `day:<localDate>`,
     * `streak:<id>:<milestone>`, `budget:<YYYY-MM>`. Unique per user, and that uniqueness
     * IS the idempotence: a replayed tap, an optimistic retry or an offline sync collides
     * here and becomes a no-op. Nothing in the award path checks-then-inserts, because
     * that races.
     */
    key: { type: String, required: true },
    amount: { type: Number, required: true, min: 1 },
    awardedAt: { type: Date, required: true, default: () => new Date() },
  },
  opts,
);

xpAwardSchema.index({ userId: 1, key: 1 }, { unique: true });

export type XpAwardDoc = InferSchemaType<typeof xpAwardSchema>;
export const XpAwardModel = model('XpAward', xpAwardSchema);
```

- [ ] **Step 2: Write the failing test**

Create `apps/api/src/modules/xp/service.test.ts`, mirroring the in-memory replica set setup in `apps/api/src/context/aggregator.invalidation.test.ts` — read that file first for the conventions.

It must cover, at minimum:

- Granting two distinct awards inserts two rows and moves `user.xp` by their sum.
- **Granting the same award twice inserts one row and moves `user.xp` once.** This is the property the whole feature turns on.
- A mixed batch where one key is new and one is a duplicate grants only the new amount.
- `grantAwards(userId, [])` is a no-op and returns 0.
- Two users may hold the same key independently.
- The returned number equals the actual delta applied to `user.xp`.

- [ ] **Step 3: Run it and confirm it fails**

Run: `pnpm --filter @synitheia/api test xp/service`
Expected: FAIL — module not found.

- [ ] **Step 4: Implement `grantAwards`**

Create `apps/api/src/modules/xp/service.ts`.

The shape that matters: for each award, attempt the insert and let a duplicate-key error mean "already granted". Sum only the amounts that actually inserted, then apply that sum to `user.xp` in a single `$inc`.

Do **not** query for existing keys first — that is a check-then-act race, and under the optimistic habit checkbox it is a live one, not a theoretical one. Mongo's duplicate-key error is code `11000`; catching exactly that and rethrowing anything else is the correct discrimination.

`user.xp` is a **cache** of the ledger sum. Say so in a doc comment, and note that the ledger is the truth and the total is recomputable from it — that is what makes drift detectable rather than permanent, and it is why this is not the bare counter that `nutrition/service.ts` warns about.

Run: `pnpm --filter @synitheia/api test xp/service`
Expected: PASS.

- Completing the last outstanding habit of the day adds the day bonus; completing a habit while others remain does not.
- Reaching a 7-day streak grants the milestone once, and a further completion at streak 8 grants nothing.

**Placeholders:** Tasks 3–5 give the wiring points and the test list rather than full code, because each is a handful of lines inside a function whose surrounding context the implementer must read anyway. Task 1 and 2 carry complete tests, and Task 1's is the specification of every amount and key.

**The risk worth stating:** the only thing protecting against double-awards is the unique index. If a future migration drops it, or a new award site does check-then-insert, XP inflates silently and nobody notices — there is no user-visible symptom of getting 20 instead of 10. Every task's tests therefore assert idempotence through the real service, not through the helper.
