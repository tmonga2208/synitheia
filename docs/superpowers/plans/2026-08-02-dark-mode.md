# Dark Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Synítheia a full dark theme — cool charcoal, following the OS with a manual override — by introducing a semantic theme layer and converting all 45 files that draw colour.

**Architecture:** `src/theme/tokens.ts` splits into raw scales (`palette.ts`), semantic tokens (`theme.ts`), and a provider (`ThemeProvider.tsx`). Colour-bearing styles move from module-level `StyleSheet.create` into `makeStyles(theme)` factories called through `useTheme()`. Dimension scales (`spacing`, `radius`, `type`, `motion`, `MIN_TAP_TARGET`) are theme-independent and keep their existing static imports, so files that use no colour need no hook. A lint rule then forbids importing raw palette outside `src/theme/`, making an unconverted file a build failure.

**Tech Stack:** React Native (Expo SDK 54), TypeScript, Zustand, `@react-native-async-storage/async-storage`, vitest, ESLint flat config.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-08-02-dark-mode-design.md`. Read it before starting.
- **Conversion is by ROLE, not by token name.** `backgroundColor: palette.bone` → `t.bg`. `color: palette.white` on a filled sage control → `t.onAccent`. A mechanical rename produces invisible icons.
- **`onAccent` deliberately inverts between themes.** Light mode lifts sage for dark backgrounds, so dark `accent` is `#89A889` — white on it measures 2.62:1 and vanishes, while near-black measures 6.86:1. Never "correct" `onAccent` back to white in dark; that is the token doing its job. (Measured during Task 2; the alternative of darkening dark-mode sage until white works leaves the accent at ~2.5:1 against the surface, where it stops reading as an accent at all.)
- **Dark surface scale:** `bg #15171A`, `surface #1A1D21`, `surfaceRaised #20242A`, `border #2C3138`. Depth comes from the step in lightness; `shadow` resolves to `shadow.none` in dark. **Light mode's values and shadows do not change.**
- **Only colour goes through the hook.** Never move `spacing`, `radius`, `type`, `motion`, or `MIN_TAP_TARGET` into the theme object's consumption path — they are invariant and must stay statically imported.
- **Contrast is computed, never asserted from memory.** This codebase already shipped a WCAG error from a remembered threshold. Body text needs 4.5:1; every exception is listed in the test with its measured ratio and a reason.
- **Never widen scope into a redesign.** Dark variants are derived by the spec's stated rules. If a light-mode colour looks wrong to you, leave it and report it.
- **Test runner:** `pnpm --filter @synitheia/mobile test`, `... typecheck`, `... lint`. Full gate: `pnpm check`.
- **Commit after every task.** Prefixes: `feat(mobile):`, `refactor(mobile):`, `chore(mobile):`.

```ts
/**
 * WCAG 2.1 contrast maths.
 *
 * This module exists because a threshold recalled from memory shipped a real
 * accessibility defect in this app once already. Every colour decision in the theme is
 * measured here rather than argued about.
 */

function parseHex(hex: string): [r: number, g: number, b: number] {
  const raw = hex.replace('#', '').trim();
  const full =
    raw.length === 3
      ? raw
          .split('')
          .map((c) => c + c)
          .join('')
      : raw;

  if (full.length !== 6) throw new RangeError(`Not a hex colour: "${hex}"`);

  return [
    Number.parseInt(full.slice(0, 2), 16),
    Number.parseInt(full.slice(2, 4), 16),
    Number.parseInt(full.slice(4, 6), 16),
  ];
}

function toChannel(value: number): number {
  const s = value / 255;
  // The sRGB transfer function. The 0.03928 knee is part of the spec, not a fudge.
  return s <= 0.03928 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4;
}

export function relativeLuminance(hex: string): number {
  const [r, g, b] = parseHex(hex);
  return 0.2126 * toChannel(r) + 0.7152 * toChannel(g) + 0.0722 * toChannel(b);
}

export function contrastRatio(a: string, b: string): number {
  const la = relativeLuminance(a);
  const lb = relativeLuminance(b);
  const lighter = Math.max(la, lb);
  const darker = Math.min(la, lb);
  return (lighter + 0.05) / (darker + 0.05);
}

function pad(n: number): string {
  return n.toString(16).padStart(2, '0');
}

/**
 * Flatten a translucent colour over an opaque one.
 *
 * Needed because several of this app's fills are alpha tints — a habit's `wash`, the
 * History grid's tint ramp — and a contrast ratio can only be computed against an
 * opaque colour. Measuring the tint against its own base rather than its composite
 * would report a number the user never sees.
 */
export function composite(fg: string, alpha: number, bg: string): string {
  const [fr, fg_, fb] = parseHex(fg);
  const [br, bg_, bb] = parseHex(bg);
  const mix = (f: number, b: number) => Math.round(f * alpha + b * (1 - alpha));
  return `#${pad(mix(fr, br))}${pad(mix(fg_, bg_))}${pad(mix(fb, bb))}`;
}
```

```ts
import { describe, expect, it } from 'vitest';
import { contrastRatio } from './contrast.js';
import { darkTheme, lightTheme, type Theme } from './theme.js';

const THEMES: [name: string, t: Theme][] = [
  ['light', lightTheme],
  ['dark', darkTheme],
];

/**
 * Pairings that do NOT meet 4.5:1, each with a reason. An exception that is not
 * written down here is a bug, not a decision.
 */
const EXCEPTIONS = [
  // White on sage. Predates dark mode: the app's primary buttons have always used it,
  // and the History grid's top tint band inherited it. Measured, not waived silently.
  { pair: 'onAccent/accent', themes: ['light'], floor: 3.3 },
  // Disabled and placeholder text. WCAG 1.4.3 exempts disabled controls.
  { pair: 'textFaint/bg', themes: ['light', 'dark'], floor: 3.0 },
  { pair: 'textFaint/surface', themes: ['light', 'dark'], floor: 3.0 },
];

function floorFor(pair: string, theme: string): number {
  const e = EXCEPTIONS.find((x) => x.pair === pair && x.themes.includes(theme));
  return e ? e.floor : 4.5;
}

describe.each(THEMES)('%s theme contrast', (name, t) => {
  const surfaces: [string, string][] = [
    ['bg', t.bg],
    ['surface', t.surface],
    ['surfaceRaised', t.surfaceRaised],
  ];
  const texts: [string, string][] = [
    ['textPrimary', t.textPrimary],
    ['textMuted', t.textMuted],
    ['textFaint', t.textFaint],
  ];

  for (const [sName, s] of surfaces) {
    for (const [tName, text] of texts) {
      it(`${tName} on ${sName} is legible`, () => {
        const ratio = contrastRatio(text, s);
        expect(ratio).toBeGreaterThanOrEqual(floorFor(`${tName}/${sName}`, name));
      });
    }
  }

  it('onAccent is legible on accent', () => {
    const ratio = contrastRatio(t.onAccent, t.accent);
    expect(ratio).toBeGreaterThanOrEqual(floorFor('onAccent/accent', name));
  });

  it('border is perceptible against surface', () => {
    // Not a WCAG text rule — a hairline that cannot be seen is not a border.
    expect(contrastRatio(t.border, t.surface)).toBeGreaterThan(1.2);
  });

  it('every habit accent’s text is legible on surface', () => {
    for (const color of Object.keys(t.habitAccents)) {
      const accent = t.habitAccents[color];
      expect(
        contrastRatio(accent.text, t.surface),
        `habit accent ${color}`,
      ).toBeGreaterThanOrEqual(4.5);
    }
  });

  it('every habit accent’s base is perceptible on surface', () => {
    for (const color of Object.keys(t.habitAccents)) {
      const accent = t.habitAccents[color];
      expect(
        contrastRatio(accent.base, t.surface),
        `habit accent ${color}`,
      ).toBeGreaterThanOrEqual(3);
    }
  });
});
```

  {
    // Raw colour scales are for the theme layer only. A component that reaches past
